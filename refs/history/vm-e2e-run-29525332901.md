## Remaining failure

```text
FAILED Failed to start bootloader-update.service - Update bootloader on boot.
See 'systemctl status bootloader-update.service' for details.
```

The enrollment-surface job (`tests/vm/test-fido2-enrollment.sh`) was skipped because the LUKS/FIDO2 boot step failed first.

## Planning implications

- Treat zstd EFI zboot as a managed compatibility guard, not the active blocker for this run. The pinned QEMU workaround proved enough to reach a booted ARM64 guest.
- Treat the next CI task as guest-level triage for `bootloader-update.service` and the VM test's failed-unit policy.
- Keep the software-authenticator path TEST-only. This run improves CI confidence but does not replace the physical YubiKey hardware validation gate.
