# skill-check — frozen content check, deterministic fixer, and wayfinder cycle driver

Written for the 2026-09-17 skills round (`refs/wayfinder-skills-round1-2026-09-17.md`) and the follow-up sweep (`refs/skills-check-sweep-2026-09-17.md`). Process rules: `tools/point-map/AGENT.md` → "Lessons learned".

- `skillcheck.sh <file> [<repo-root>]` — independent content check, exit text `TASK CHECK: PASS|FAIL`. C1 mojibake/replacement bytes; C2 duplicate `##` headings; C3 "TBD per file context / TODO: refine" placeholders; C4 SKILL.md frontmatter per the skill-format spec (closed block, `name` `^[a-z0-9-]{1,64}$`, `description` 1..1024 chars, no `<`/`>`); C5 template capability paragraphs; C6 unresolved local links. C7 (added later, after 362 reference/script files were found committed base64-encoded) flags a body that is entirely base64 and decodes as UTF-8. Python 3 stdlib only. Freeze it before looking at any rung. **Known limitation (SKC-4, deliberately not changed because the check is frozen):** C1 matches only the bytes `â` / U+FFFD, so `Ã©`-class mojibake (which the fixer repairs) is not detected, and a legitimate `â` (e.g. "château") is flagged although the fixer cannot and should not change it.
- `fixer.py <in> <out>` — deterministic repairs for exactly those classes (C7: any base64-committed body is decoded, including reference/script files that do not start with `---`; decoded non-Markdown files are returned verbatim and never run through the Markdown section repairs; mojibake; description overflow moved verbatim to an "Extended description" section; angle brackets; placeholder sections dropped; template paragraphs → dated coverage note; duplicate sections merged into the first, keeping all non-duplicate text). When angle brackets are stripped from a description that is also moved to the body, the inserted note says "wording unchanged apart from removal of angle brackets". Never invents content. If the result still fails the check, revert and record `declined`.
- `wayfinder-cycle.py` — one wayfinder cycle against a live baseline: top untouched CHANGE rung (ADD rungs declined and recorded once per sector; exemplar fallback on exhaustion) → pending ledger row → check → fixer → check → single-file commit on the held branch → after-map on the chained `baseline_id` with the exact baseline name set → `kept` verdict row. Environment: `WAYFINDER_CORPUS_ROOT` (checkout containing `paths.txt`), `WAYFINDER_STATE` (state JSON with `branch`, `branch_sha`, `latest`, `touched`, `declined_adds`, `cycles`); `baseline_names.json` next to the state file. GitHub calls need the repo credential in the environment's proxy. **Every API call is status-checked** (`need()` raises `ApiError` on any non-2xx): a failed `GET /api/maps/{latest}` aborts the cycle instead of being recorded as `no-untouched-change-rung`; a failed blob / tree / commit / ref `PATCH` restores the working file, records a `declined` (commit failed) row, leaves `branch_sha` unchanged and exits 1 — it never writes a `kept` row; a failed `kept` ledger POST after a successful commit records `committed-but-verdict-row-failed` (the branch did advance) and exits 1. The verifier string recorded in the ledger now reads "C1-C7 (C1-C6 frozen 2026-09-17 before the round; C7 added after it)".

Sweep recipe (no geometry): run `skillcheck.sh` over every file, apply `fixer.py` to the failures, re-check, commit the passing set as one PR stacked on the round branch.
